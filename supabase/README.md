# Supabase — So'z Jangi daily backend

Server-authoritative daily puzzle: the client never holds the answer. Guess
scoring and dictionary validation happen inside the `evaluate-guess` Edge
Function (service role); clients read only the non-secret
`daily_puzzle_public` view. The bundled schedule asset is the **offline
fallback** (see "Client wiring"), not the primary source.

## Schema (normalised)

```
words(id, word UNIQUE, normalized_word = upper(word) [generated, UNIQUE],
      length, tier, theme, is_answer_candidate, created_at)

daily_puzzles(id, puzzle_number UNIQUE, puzzle_date UNIQUE,
              word_id -> words.id, theme_override, created_at)

daily_puzzle_public  (view)  -> puzzle_number, puzzle_date, word_length,
                                theme, locked_prefix_raw   [today-or-past only]
```

- The **answer** is `words.word`, referenced by `daily_puzzles.word_id`. It is
  never exposed: `words` and `daily_puzzles` have their SELECT grants revoked
  from `anon`/`authenticated`; only `service_role` (inside the Edge Function)
  can read them.
- `daily_puzzle_public` is an invoker-rights view filtered `puzzle_date <=
  current_date`, so future answers/metadata are never queryable. It exposes
  `locked_prefix_raw = left(normalized_word, 2)` (2 chars so a compound Uzbek
  letter `oʻ`/`gʻ` is never truncated for the WS4 first-letter reveal).

## Files
- `migrations/*.sql` — the exact applied DDL history of `soz-jangi-prod`
  (pulled from `supabase_migrations.schema_migrations`). `db push` against that
  project is a clean no-op. The final migration (`insert_test_daily_puzzle`) is
  a one-off smoke row superseded by the real seed; a fresh project may skip it.
- `functions/evaluate-guess/index.ts` — the scoring + word-validation function.
- `seed/seed_from_schedule.py` — turns `tool/generator/out/schedule.json` into
  an idempotent `daily_puzzles` upsert (`seed/seed_daily_puzzles.sql`) for the
  normalised schema (resolves each word to `words.id`).
- Dictionary seed: `tool/corpus/output/words_import.sql`, generated by
  `tool/corpus/export_supabase.py` from the curated corpus (6766 words,
  `ON CONFLICT (word) DO NOTHING`). This is the single bridge that keeps
  Practice's bundled dictionary and Daily's `words` table from diverging.

## Deploy from zero

```bash
# 0. Link the project
supabase link --project-ref <ref>

# 1. Schema
supabase db push                       # applies migrations/*.sql

# 2. Dictionary (6766 words) — REQUIRED before the schedule seed and before the
#    Edge Function will accept any real guess as a valid word.
psql "$SUPABASE_DB_URL" -f tool/corpus/output/words_import.sql
#    (or paste it in the Supabase SQL editor; idempotent, ON CONFLICT DO NOTHING)

# 3. Schedule (90 days) — resolves each scheduled word to words.id
python3 tool/generator/generate_schedule.py \
    --answers tool/corpus/out/answers_tiered.tsv \
    --start <tomorrow> --start-number <next#> --days 90 --seed 142 \
    --history tool/generator/out/schedule.json \
    --out tool/generator/out/schedule.json
python3 supabase/seed/seed_from_schedule.py \
    --schedule tool/generator/out/schedule.json \
    --out supabase/seed/seed_daily_puzzles.sql
psql "$SUPABASE_DB_URL" -f supabase/seed/seed_daily_puzzles.sql

# 4. Edge Function
supabase functions deploy evaluate-guess       # verify_jwt = true

# 5. Rebuild the bundled offline asset from the same schedule.json
python3 - <<'PY'
import gzip
data = open('tool/generator/out/schedule.json','rb').read()
with gzip.GzipFile('assets/dictionary/schedule.json.gz','wb',mtime=0) as g:
    g.write(data)
PY
```

Steps 2–4 can also be run via the Supabase MCP tools (`execute_sql` for the
seeds, `deploy_edge_function` for the function) against the project ref.

### Verify (server == bundle)
`daily_puzzle_public` hides future rows, so verify future dates with a
service-role read:
```sql
select dp.puzzle_date, dp.puzzle_number, w.word, w.length,
       left(w.normalized_word,2) as locked_prefix_raw
from daily_puzzles dp join words w on w.id = dp.word_id
where dp.puzzle_date in ( /* 5 random future dates */ );
```
Each row must equal the corresponding entry in `assets/dictionary/schedule.json.gz`
(`puzzle_number`, `upper(word)`, `word[:2]`).

## Client wiring (app)
`DailyPuzzleRepository` is server-primary with an automatic offline/latency
fallback. `SupabaseDailyPuzzleRepository` calls the view + Edge Function; when it
is offline, times out (>2.5s), or 5xx's, `FallbackDailyPuzzleRepository` scores
the guess locally against the bundled `schedule.json.gz` answer for that date, so
the daily board stays fully playable with no network. Local guess pre-validation
(`Dictionary.contains`, from the bundled `valid_guesses.txt.gz`) is the instant
first check, so "not a word" never needs the network.
